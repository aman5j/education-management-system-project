## Architecture

Central platform collections:
- superadmins
- institutes
- domains
- plans
- subscriptions
- provisioninglogs
- platformauditlogs
- platformsettings

Institute collections use this namespace:

inst_<institute-object-id>_<collection-name>

Examples:
- inst_<id>_students
- inst_<id>_users
- inst_<id>_courses
- inst_<id>_studentadmissions
- inst_<id>_payments
- inst_<id>_examresults

The collection prefix is generated by the backend. Browser input must never select it.

### InstituteSettings.js
- key defaults to "default".
- key is unique and immutable.
- This is a singleton-style settings model and must become institute-local.

### Institute.js
- slug is unique.
- databaseName is unique.
- collectionPrefix is introduced by Phase 3A and is generated from the institute ID.

## Important implementation risks

1. Existing models currently use global mongoose.model() exports.
2. Existing controllers import global model instances.
3. Mongoose populate references must be rewritten to tenant-specific model names when models share one MongoDB connection.
4. Unique indexes must be created separately in each institute collection.
5. Singleton settings must be stored in each institute's own prefixed collection.
6. Existing global collections must not be dropped or renamed during migration.
7. Public routes and background jobs also require tenant resolution.
8. Upload paths are not isolated by this phase.
